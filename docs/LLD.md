# Low-Level Design (LLD)

## Important Modules & Classes

### Models (`backend/models.py`)
- `PatientInput`: Pydantic schema for incoming patient data.
- `TriageResult`: Schema for the result generated by the triage engine.

### Triage Engine
- `patient_validator.py`: Checks for missing fields (vitals, history).
- `triage_rules.py`: Determines LEVEL 1 to 5 based on vital thresholds (e.g. HR > 150 = LEVEL 1) and text matching in chief complaint. Features specific logic for pediatric/geriatric patients.
- `uncertainty_calculator.py`: Decrements a confidence score (base 1.0) for missing fields and ambiguous symptoms. Triggers safety escalation if uncertainty is high alongside missing history.
- `triage_explanation.py`: Orchestrator that aggregates results from the above modules.

### Queue Monitor (`backend/queue/queue_monitor.py`)
- `QueueMonitor` class: In-memory dictionary mapping patient IDs to `QueueItem`s. Evaluates wait times against a threshold (60s default) to flag reassessment. Evaluates worsening vitals to trigger escalation flags.

### Audit Logger (`backend/audit/audit_logger.py`)
- `AuditLogger` class: Maintains an append-only in-memory list of `OverrideRecord` objects detailing clinician overrides.

## API Flow
1. `POST /api/triage`: Calls `perform_triage()`, then `queue_manager.add_patient()`.
2. `GET /api/queue`: Calls `queue_manager.get_queue()` which first updates wait-time flags.
3. `POST /api/queue/vitals`: Updates vitals via `queue_manager.update_vitals()`.
4. `POST /api/override`: Mutates a patient's priority in the queue and adds an audit entry via `audit_logger.log_override()`.
5. `POST /api/surge`: Loads all 20 simulated patients at once and lowers the wait threshold to 10 seconds to simulate a rapid influx of patients and quick reassessment triggers.
